## Why

UX мини-приложения не готов к реальным пользователям: анимация свайпа дёргается (карточка «отстаёт» от пальца из-за transform через React state на каждый кадр + `transition-transform` + тяжёлые `backdrop-blur`), при старте видны артефакты (мигание баннера «Telegram ID not set», спиннер → мгновенный поп-ап карточки без анимации, поздний подгруз постера), а свайпы регистрируются ненадёжно: жесты теряются (не обрабатывается `touchcancel`), свайп определяется только по порогу 100px без учёта скорости, и на время сетевого запроса весь UI тихо блокируется — из-за чего складывается впечатление, что «свайп засчитывается только с N-й попытки».

## What Changes

- **Плавный drag**: transform карточки переводится на императивную анимацию (ref + `requestAnimationFrame`, либо `framer-motion`/`react-swipeable`), а не на React state; убрать `transition-transform` во время драга (transition только для snap-back/throw); добавить `will-change: transform`; убрать/упростить `backdrop-blur` на движущейся карточке.
- **Регистрация жеста**: Pointer Events вместо touch-обработчиков + обработка `pointercancel`; определение флика по скорости (velocity) в дополнение к порогу дистанции.
- **Анимация вылета/входа**: при свайпе карточка «улетает» в направлении жеста, следующая появляется с плавным `scale-in` — видимый фидбек, что свайп засчитан.
- **Оптимистичный свайп**: карточка уходит сразу, запрос уходит в фоне; при ошибке — возврат карточки + понятное сообщение, а не молчаливая блокировка. Вместо глобального `isSwipeInProgress` — точечная индикация отправки.
- **Старт приложения**: skeleton вместо голого спиннера; ожидание инициализации Telegram WebApp SDK до определения личности (без мигания баннера); preload постера следующей карточки; плавное появление первой карточки.
- **Спринт-репро**: маленькое исследование для воспроизведения «свайп засчитывается только с 5-й попытки / после 5 свайпов подряд» на реальном устройстве в Telegram и фиксация конкретного триггера.

## Capabilities

### New Capabilities

- `ui/swipe-interaction`: жесты свайпа — плавный drag без дёрганья, флик по скорости, анимация вылета и входа карточки, надёжная регистрация жеста (без потерь `touchcancel`), видимый фидбек о засчитанном свайпе и об ошибках.
- `ui/app-bootstrap`: корректная инициализация при старте — ожидание Telegram WebApp SDK, skeleton, отсутствие мигающих заглушек, плавный вход первой карточки.

## Impact

- **Frontend**: `frontend/src/components/MovieCard.tsx` (переписать обработку жестов и анимацию), `frontend/src/App.tsx` (startup-flow, снятие глобальной блокировки свайпов, оптимистичная отправка), `frontend/src/index.css`/`tailwind.config.ts` (анимации, ключевые кадры, отключение blur во время драга), `frontend/src/services/api.ts` (обработка ошибок/429).
- **Зависимости**: добавление `framer-motion` (или `react-swipeable`, если без библиотек) в `package.json`.
- **Backend**: не затрагивается напрямую (кроме возможного эндпоинта статуса отправки свайпа, если понадобится для оптимистичного фидбека).
