## Purpose

Корректная инициализация мини-приложения при старте: ожидание Telegram WebApp SDK, отсутствие мигающих заглушек, плавный вход первой карточки вместо резкого появления.

## ADDED Requirements

### Requirement: Ожидание готовности Telegram WebApp SDK

Приложение SHALL определять личность пользователя только после инициализации Telegram WebApp SDK; интерфейс не должен показывать ошибочные заглушки раньше времени.

#### Scenario: SDK загружен
- **WHEN** Telegram WebApp SDK доступен и предоставляет initData
- **THEN** приложение использует initData для идентификации без мигания заглушки об отсутствии Telegram ID

#### Scenario: SDK недоступен в prod
- **WHEN** приложение открыто вне Telegram WebApp и initData недоступен
- **THEN** показывается корректное состояние (без имитации работы свайпов), dev-фоллбэк применяется только в development-режиме

#### Scenario: Медленная загрузка SDK
- **WHEN** SDK инициализируется дольше обычного
- **THEN** интерфейс дожидается инициализации, а не показывает мгновенный сброс состояния

### Requirement: Плавный вход первой карточки

Первая карточка и последующие SHALL появляться с плавной анимацией, без резкого «поп-апа» и без позднего перескакивания из-за подгрузки постера.

#### Scenario: Загрузка завершена
- **WHEN** данные первой карточки загружены
- **THEN** карточка появляется с плавной анимацией входа

#### Scenario: Постер ещё грузится
- **WHEN** постер карточки ещё не загружен
- **THEN** во время загрузки постера отображается консистентное состояние без перескакивания контента после подгрузки

### Requirement: Скелетон вместо голого спиннера

Во время первичной загрузки SHALL отображаться скелетон карточки (структура будущего контента), а не только крутилка.

#### Scenario: Первичная загрузка
- **WHEN** приложение загружает первую порцию фильмов
- **THEN** вместо голого спиннера показывается скелетон карточки
