## Why

Сейчас `GET /api/movies/random` отдаёт каждому участнику комнаты свой случайный фильм из общей базы. Два друга в одной комнате почти никогда не видят один и тот же фильм → матч («все участники лайкнули один фильм») практически невозможен. Свайп-механика, ради которой продукт и существует, не работает в групповом сценарии.

## What Changes

- **Общий колод фильмов для комнаты**: все участники комнаты получают одну и ту же упорядоченную последовательность фильмов.
- **Свайп-позиция комнаты**: сервер запоминает текущую позицию колода для комнаты; `GET /api/movies/random` возвращает следующий непросвайпанный фильм комнаты для текущего пользователя.
- **Без повторов**: фильм, который участник комнаты уже свайпнул, не предлагается снова в рамках комнаты.
- **Дека-состояние**: хранение состава/позиции колода (новая таблица или поле комнаты), наполнение колода (переиспользование существующей загрузки из Kinopoisk).
- **Совместимость**: API остаётся совместимым для фронта (тот же эндпоинт, но теперь учитывает комнату); вне комнаты поведение прежнее (случайный фильм).
- **BREAKING** (внутреннее): `movie_service.get_random_movie` меняет семантику для участников комнат — клиенты должны передавать контекст комнаты.

## Capabilities

### New Capabilities

- `rooms/shared-deck`: общий упорядоченный колод фильмов на комнату, позиция свайпов комнаты, отсутствие повторов для участников, наполнение и исчерпание колода.

## Impact

- **Backend**: `app/api/movies.py` (эндпоинт random с учётом комнаты), `app/api/schemas.py`, `app/services/movie_service.py` (выбор следующего фильма комнаты), `app/services/room_service.py`, новая модель/таблица для колода комнаты + alembic-миграция.
- **Frontend**: `frontend/src/services/api.ts` и `frontend/src/App.tsx` — передача контекста комнаты в запрос случайного фильма.
- **Данные**: миграция БД (таблица колода/позиции комнат).
- **Зависимость от других change**: не зависит от `deploy-readiness` и `swipe-ux`, но UX свайпов обретает смысл только вместе с этим фиксом.
