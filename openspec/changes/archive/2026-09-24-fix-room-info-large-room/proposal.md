## Why

Команда бота `/room_info` падает с общей ошибкой «❌ Произошла ошибка при получении информации о комнате» (issue [#3](https://github.com/Lotreamaun/tinder_movie/issues/3)), когда в комнате 3+ участника. Причина — `handlers.py` подставляет `first_name`/`username` участников в сообщение без экранирования и отправляет его с `parse_mode='Markdown'`; если у кого-то из участников в имени/юзернейме встречается спецсимвол Markdown (`_`, `*`, `` ` ``, `[`) без пары, Telegram Bot API отвечает 400 «Can't parse entities», это падает в общий `except Exception` и пользователь видит бесполезную ошибку вместо списка участников. Баг не завязан на число «3» жёстко — он завязан на вероятность встретить спецсимвол хотя бы у одного участника, которая растёт с числом участников (подтверждено исследованием; см. `backend/app/bot/handlers.py:260-271`).

## What Changes

- Убрать `parse_mode='Markdown'` из сообщения `/room_info` — эти данные (имя/юзернейм) приходят от пользователя и не должны интерпретироваться как разметка; отправлять сообщение обычным текстом.
- Добавить тест на формирование сообщения `/room_info`, покрывающий имена/юзернеймы со спецсимволами Markdown (`_`, `*`, `` ` ``, `[`), чтобы регрессия не повторилась.

## Capabilities

### New Capabilities
- `rooms/room-info`: команда бота `/room_info` должна надёжно показывать список участников комнаты независимо от содержимого их имени/юзернейма в Telegram.

### Modified Capabilities
(нет — команда `/room_info` ранее не была описана в спеках)

## Impact

- `backend/app/bot/handlers.py` — обработчик `room_info` (формирование и отправка сообщения, строки ~260-271).
- Тесты бота (новый файл `backend/tests/test_bot_handlers.py` или аналогичный) — тест на формирование текста сообщения `/room_info`.
- Поведение остальных Markdown-сообщений бота (`create_room`, `join_room`) не меняется — там интерполируется только код комнаты (буквы/цифры) и число участников, спецсимволов там не бывает.
