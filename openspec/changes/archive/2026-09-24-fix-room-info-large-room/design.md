## Context

`backend/app/bot/handlers.py` строит текст ответа `/room_info` конкатенацией строк и отправляет его через `update.message.reply_text(message, parse_mode='Markdown')`. `first_name`/`username` участников приходят из Telegram без какой-либо очистки и подставляются в сообщение как есть (см. proposal.md — Why). Легаси-режим `Markdown` у Telegram Bot API требует парных спецсимволов (`_`, `*`, `` ` ``, `[`); непарный символ в имени/юзернейме любого участника приводит к 400 `Can't parse entities`, которая тонет в общем `except Exception`.

## Goals / Non-Goals

**Goals:**
- `/room_info` должен успешно отправлять сообщение при любом содержимом `first_name`/`username` участников и при любом (до `MAX_ROOM_SIZE`) числе участников.
- Не терять существующую информацию в сообщении (код комнаты, число участников, список имён/юзернеймов, дата создания).

**Non-Goals:**
- Не трогаем `create_room`/`join_room` — там интерполируется только код комнаты (буквы/цифры) и число участников, спецсимволов Markdown там не бывает.
- Не вводим сложное экранирование под `MarkdownV2` — оно не требуется, раз форматирование самого текста не критично для этого сообщения.
- Не меняем обработку реальных ошибок (`ValueError` → "комната не найдена", остальное → generic + `logger.error`).

## Decisions

**Убрать `parse_mode='Markdown'` из ответа `/room_info`, отправлять как обычный текст.**

Альтернатива — экранировать пользовательский текст через `telegram.helpers.escape_markdown(text, version=1)` перед подстановкой и сохранить Markdown-форматирование (например, моноширинный код комнаты). Отклонено: усложняет код ради косметики (моноширинный код комнаты — не критичная фича), а `escape_markdown` — ещё одно место, которое легко забыть при будущих правках сообщения. Обычный текст полностью устраняет класс бага (любые пользовательские данные безопасны) и не имеет других уместных здесь спецсимволов, которые нужно было бы стилизовать.

## Risks / Trade-offs

[Сообщение `/room_info` теряет моноширинное выделение кода комнаты и общее Markdown-форматирование] → приемлемо: код комнаты и так выделен эмодзи-префиксом `🏠`, а надёжность важнее косметики.

[В будущем кто-то добавит новую Markdown-разметку в другое сообщение бота, куда подставляется пользовательский текст, и повторит тот же баг] → вне рамок этого фикса; сам факт бага и его причина зафиксированы в спеке `rooms/room-info`, что даёт прецедент для ревью подобных изменений.
