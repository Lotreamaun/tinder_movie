## Why

Фоновая догрузка каталога (change `fix-movie-catalog-exhaustion`) структурно не способна найти новые фильмы. `load_batch_movies` берёт единственный источник — подборку `TOP_250_BEST_FILMS` — каждый раз начинает с первой страницы и обрывается жёстким лимитом `page > 10`. Страница содержит 20 фильмов, поэтому догрузке доступны только первые 200 фильмов топа, а в топе 13 страниц (250 фильмов; проверено запросом к API). В каталоге уже 204 фильма, все первые 200 известны, так что любая попытка догрузки гарантированно даёт 0 новых фильмов, тратит 10+ запросов квоты и ставит паузу.

Лог 2026-09-24 18:38 это подтверждает: `remaining=29` → 10 страниц по «Successfully loaded 0 movies» → `Grew catalog by 0 movies` → cooldown. За один вечер один участник просвайпал 186 фильмов из 204 и дальше жил только на рецикле колоды. Этот источник исчерпания отмечен как Open Question в `archive/2026-09-24-fix-movie-catalog-exhaustion/design.md`; теперь это рабочий баг.

## What Changes

- Догрузка каталога ходит по **нескольким подборкам Kinopoisk** по порядку из настраиваемого списка (по умолчанию `TOP_250_MOVIES`, затем `TOP_POPULAR_MOVIES` — 700 фильмов), а не по одной `TOP_250_BEST_FILMS`.
- Пагинация идёт до реального конца подборки (`totalPages` из ответа), а не до зашитого лимита в 10 страниц. Число страниц **за одну попытку** ограничивается бюджетом, чтобы не выжигать квоту.
- Догрузка **продолжает с места, где остановилась** в прошлый раз (подборка + страница), а не начинает каждый раз с первой страницы известных фильмов. Когда все подборки пройдены, следующий проход начинается сначала: популярные подборки со временем меняются.
- Источник переводится на эндпоинт подборок `/api/v2.2/films/collections`: он сразу отдаёт все поля фильма, поэтому отдельный запрос полных данных на каждый новый фильм больше не нужен, и один новый фильм стоит в разы меньше квоты.
- В каталог попадают только фильмы (`type = FILM`): сериалы из подборок отсеиваются.
- **Учёт исчерпания подборок.** Число новых фильмов накапливается за полный проход всех подборок, который может занять несколько попыток. Если проход закончился и не нашёл ни одного нового фильма, подборки считаются исчерпанными: догрузка ставится на **длинную паузу** (по умолчанию 7 дней, настраиваемо), после чего один проход проверяет новинки. Без этого, когда всё уже загружено, каждая попытка по порогу тратила бы до 15 запросов квоты впустую.
- **Пауза зависит от причины остановки попытки.** Короткая пауза (30 минут, как сейчас) остаётся только для ошибок источника: сеть, 402, 5xx. Попытка, которая упёрлась в бюджет страниц, паузу не ставит, даже если ничего не нашла: проход не закончен, и следующая попытка продолжит его. Попытка останавливается на конце прохода и не начинает следующий в том же бюджете.
- Логи догрузки показывают подборку, страницу и число новых фильмов, вместо вводящей в заблуждение строки «Successfully loaded 0 movies» на каждую страницу.

## Capabilities

### New Capabilities

_Нет._

### Modified Capabilities

- `rooms/shared-deck`: добавляется требование к источнику догрузки каталога: догрузка не должна упираться в фиксированный потолок одной подборки и должна находить новые фильмы, пока они есть хотя бы в одной из настроенных подборок. Требование «Наполнение и исчерпание колода» меняется: пауза догрузки теперь зависит от причины остановки (ошибка → короткая, подборки исчерпаны → длинная, исчерпан бюджет страниц → без паузы), а не ставится после любой пустой попытки.

## Impact

- `backend/app/services/movie_service.py`: `load_batch_movies` (возвращает результат попытки с причиной остановки вместо голого числа), `get_top_movies_from_kinopoisk` (заменяется выборкой страницы подборки), общий маппинг полей Kinopoisk → `Movie` (выносится из `fetch_movie_from_kinopoisk`), курсор прохода по подборкам и счётчик новых фильмов за проход.
- `backend/app/config.py`: список подборок, бюджет страниц на попытку, длинная пауза при исчерпании подборок.
- `backend/app/services/deck_service.py`: `_run_background_growth` выбирает паузу по причине остановки попытки (сейчас пауза ставится при любом `loaded == 0`).
- `backend/tests/test_shared_deck.py`: тесты на догрузку, в том числе переделка `test_load_batch_movies_continues_past_fully_known_page`.
- Внешняя зависимость: другой эндпоинт `kinopoiskapiunofficial.tech` (`/api/v2.2/films/collections`; тот же ключ, та же квота).
- Схема БД не меняется, миграция не нужна.
