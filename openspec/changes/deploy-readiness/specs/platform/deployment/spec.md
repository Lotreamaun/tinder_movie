## Purpose

Инфраструктура развёртывания продукта: контейнеризация backend и frontend, docker-compose для полного стека, автоматическое применение миграций и CI/CD-пайплайн.

## ADDED Requirements

### Requirement: Контейнеризация backend

Backend SHALL собираться в Docker-образ, запускающий FastAPI-приложение, со всеми зависимостями из `requirements.txt` и корректным `.dockerignore`.

#### Scenario: Сборка образа backend
- **WHEN** выполняется `docker build` для backend
- **THEN** создаётся образ, который запускает FastAPI-приложение и не содержит файлов окружения/логов разработки

#### Scenario: Запуск контейнера backend
- **WHEN** контейнер backend запускается с настроенными переменными окружения
- **THEN** FastAPI отвечает на `GET /health` с HTTP 200

### Requirement: Контейнеризация frontend

Frontend SHALL собираться в статический артефакт и раздаваться веб-сервером, проксирующим `/api/*` на backend.

#### Scenario: Сборка образа frontend
- **WHEN** выполняется `docker build` для frontend
- **THEN** создаётся образ, содержащий собранный SPA и веб-сервер

#### Scenario: Проксирование API
- **WHEN** браузер запрашивает `/api/...` у frontend-сервиса
- **THEN** запрос проксируется на backend-сервис и ответ возвращается клиенту

### Requirement: Запуск полного стека через docker compose

Деплой SHALL запускаться через `docker compose`, который поднимает базу данных, backend API, бота и frontend.

#### Scenario: Полный стек
- **WHEN** выполняется `docker compose up`
- **THEN** поднимаются база данных, API, бот и frontend, и API доступен на ожидаемом адресе

#### Scenario: Перезапуск контейнера
- **WHEN** контейнер API перезапускается
- **THEN** приложение стартует заново и продолжает обслуживать запросы

### Requirement: Миграции при деплое

Перед стартом API в контейнере SHALL выполняться применение миграций (`alembic upgrade head`); API SHALL начинать приём трафика только после успешного применения.

#### Scenario: Старт API с миграциями
- **WHEN** API-контейнер стартует
- **THEN** миграции схемы применяются до приёма HTTP-трафика

#### Scenario: Ошибка миграции
- **WHEN** применение миграций завершается ошибкой
- **THEN** контейнер завершается с ошибкой и не принимает трафик

### Requirement: CI/CD пайплайн

Пуш в репозиторий SHALL запускать CI, который выполняет линт, тесты и сборку образов; публикация образов SHALL быть возможна только при успешном прохождении всех шагов.

#### Scenario: Пуш с ошибкой линта
- **WHEN** изменения не проходят линт
- **THEN** CI завершается с ошибкой и образ не публикуется

#### Scenario: Пуш с зелёным пайплайном
- **WHEN** линт, тесты и сборка образов проходят успешно
- **THEN** образы собираются и публикуются в registry

### Requirement: Секреты только из окружения

Чувствительные настройки (токен бота, ключ Kinopoisk, секреты) SHALL читаться только из переменных окружения. Приложение SHALL завершаться с понятной ошибкой при отсутствии обязательной переменной, а не использовать значение-заглушку.

#### Scenario: Отсутствует обязательная переменная
- **WHEN** приложение стартует без обязательной переменной окружения (например, `TELEGRAM_BOT_TOKEN`)
- **THEN** запуск завершается с понятным сообщением об ошибке

#### Scenario: Нет боевых секретов по умолчанию
- **WHEN** переменная окружения не задана
- **THEN** система не подставляет боевой секрет в качестве значения по умолчанию
