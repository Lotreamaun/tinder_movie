## Purpose

Подтверждение личности пользователей Telegram Mini App на сервере через проверку подписи Telegram WebApp initData, чтобы API перестало доверять клиентскому заголовку telegram-id.

## ADDED Requirements

### Requirement: Валидация initData Telegram WebApp

Система SHALL проверять подпись Telegram WebApp `initData` (алгоритм: HMAC-SHA256 с ключом, производным от токена бота, секретная часть — HMAC-SHA256(bot_token, "WebAppData")) для каждого запроса, требующего идентификации пользователя. Запросы с невалидной или истёкшей подписью SHALL отклоняться с HTTP 401.

#### Scenario: Валидный initData
- **WHEN** клиент отправляет запрос с корректно подписанным и непросроченным initData
- **THEN** система принимает личность пользователя из initData и обрабатывает запрос

#### Scenario: Подменённый initData
- **WHEN** клиент отправляет запрос с изменённым содержимым initData (например, подменённым `user.id`)
- **THEN** система возвращает HTTP 401 и не выполняет операцию

#### Scenario: Истёкший initData
- **WHEN** дата авторизации `auth_date` в initData старше допустимого порога
- **THEN** система возвращает HTTP 401 и требует актуальный initData

#### Scenario: Отсутствующий initData
- **WHEN** запрос к защищённому эндпоинту не содержит initData
- **THEN** система возвращает HTTP 401

### Requirement: Защищённые эндпоинты используют проверенную личность

Эндпоинты, ранее полагавшиеся на заголовок `telegram-id` (свайпы, комнаты, матчи), SHALL требовать проверенную личность. Значение из клиентского заголовка SHALL игнорироваться; `telegram_id` берётся только из проверенного initData.

#### Scenario: Свайп с проверенной личностью
- **WHEN** аутентифицированный пользователь создаёт свайп
- **THEN** сервер определяет `telegram_id` из проверенного initData, а не из заголовка запроса

#### Scenario: Свайп без аутентификации
- **WHEN** запрос на создание свайпа не содержит валидного initData
- **THEN** система возвращает HTTP 401 и свайп не создаётся

#### Scenario: Подделанный telegram-id заголовок
- **WHEN** клиент отправляет заголовок `telegram-id` одного пользователя, а проверенный initData принадлежит другому
- **THEN** система обрабатывает запрос от пользователя, подтверждённого initData, игнорируя заголовок

### Requirement: Публичные эндпоинты остаются открытыми

Публичные эндпоинты (`GET /health`, документация) SHALL оставаться доступными без аутентификации.

#### Scenario: Запрос health
- **WHEN** сервис получает `GET /health`
- **THEN** возвращается HTTP 200 без требования initData
